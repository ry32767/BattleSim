# AIエージェントの作業規約

## 正典

v0.8の現行ゲームエンジンはdocs/runtime-r1.mdのR1.3、爆発・構造破壊の具体値と境界はdocs/map-spec.mdのD1.1を優先する。過去のR0/R1.0〜1.2と矛盾したらR1.3を採用。原作シミュ→同時期ランク戦の参照順を全戦闘規則へ適用し、数式補完を公式値と呼ばない。B1は固定した未校正基準、U-D1/U-D2未試験。M1.1を変更せず新Map版へ生成。R13-T1〜T10/D11-T1〜T5は未実装・未試験。観測台帳は変更しない。

v0.7.4の現行規則はR1.2、爆発・構造破壊はdocs/map-spec.mdのD1を優先する。不壊は旧試作の条件。公式S21のトリオン量による規模調節と、独自の応答曲線/式/材料耐久/校正指標を区別する。千佳25と参考38を混在させず観測台帳を変更しない。人物名で破壊力を分岐しない。D1-T1〜T6/U-D1/U-D2は未実装・未試験。M1.0/M1.1を保存し新しい動的地形版を作る。

v0.7.3の射線・光学視界・死角はdocs/map-spec.mdのG1とdocs/runtime-r1.mdのR1.1を優先する。判定用3D solidと表示形状を同一生成器から作る。自セル/対象セルの建物一括除外、隣接低所の固定死角、2D投影からの遮蔽判定は採用しない。G1-T1〜T7はP2で実装・検証する予定で、現行M1.1ビューアには未実装。G1の固定形状比率とカメラ用renderScaleを区別し、形状変更は新Map/Rule版へ保存する。

v0.7.2の現行地形はM1.1。住宅密度・道路幅・描画階高・人物比較はdocs/map-spec.mdのM1.1節とM12を優先する。実距離換算は未確定。data/maps/M1.0の旧3JSONを改変しない。renderScaleの表示比率を戦闘の高さ/APへ流用しない。

v0.7.1の地形参照方針はdocs/map-spec.md。シミュの直接観測を優先し、地形の不足はランク戦を主に参考に補う。M1.0は機能確認用の仮配置。再現版は場面参照・シミュとの対応/補完・装備別期待到達性を確認し新Map版で固定する。全屋上へ通常到達させるための根拠のない足場を再現版へ追加しない。

v0.7の実装判断はdocs/implementation-plan.md、R1.2の演算契約はdocs/runtime-r1.md、M1.0の地形契約はdocs/map-spec.md。同じ論点では旧R0や過去の「未確定」記述よりこの決定を優先する。ルール設計の解消と全キャラ・装備・効果データの完成は区別する。通常演習の完成版が未実装という状態を維持する。

READMEは利用者向け。ゲーム仕様はdocs/spec.md、描画の基準はdocs/visual-reference.md、根拠はdocs/sources.md。このファイルに作業規約と検証手順を集約する。

原作再現・能力補完の過去監査はdocs/reproduction-policy.md。R0は試作専用、R1.2の実装規則はdocs/runtime-r1.mdで固定。BBF参考能力をシミュ観測台帳へ直接転記せず、時期・装備・根拠を持つ別の補完マスターを作る。原因説明・同時群・再生・当時視点はdocs/visual-reference.mdとR1の契約に従う。

v0.4の再監査はdocs/rule-review.md。セルと無関係な建物描画を避け、占有セル・屋上・駒・経路を対応させる。旧R0の行動数/時間/方向制限を原作確定値としてR1へ継承しない。最新リプレイは通常画面の編集状態を保持する独立ポップアップ。

v0.5の探知・タグはdocs/radar-tags.md。未視認の敵は陣営別の観測報告だけを描き、真の位置・高さ・装備・名前を流用しない。自動番号は補助機能で、原作の確定機能ではない。公式Twitter用アイコンS17の用途制限の記録と、ユーザーの非公開・個人用モックへの採用指示を区別する。最新の個人用モックでは公式URLを盤面アイコンとして参照し、公開・配布用素材に同梱しない。レーダーは点と番号/タグのみ。

コンテンツ照合はdocs/character-audit.md、docs/weapon-audit.mdとdata/の台帳を使用する。データは監査記録であり未確認値を含む。simulation_loadout=nullやskills_complete=falseのまま完成済みゲームマスターへ変換しない。通常装備の採用・能力補完・効果定義を明示した別バージョンを作る。匿名武器行の推定候補名を確定IDに自動結合しない。段階IIIの5体差は出典差がある暫定値。

資料の整合性検査は`python3 tools/validate_spec.py`。JSON参照、全64名、装備41種、画像ファイルのハッシュ、ローカルリンクを確認する。ゲームエンジンのテストではない。

Windowsの既定文字コードがcp932の場合は`python -X utf8 tools/validate_spec.py`を使う（2026-10-06に実行確認）。

地形は`python -X utf8 tools/build_maps.py`で再生成、`python -X utf8 tools/validate_maps.py`で検証する。ビューアの元はtools/map-preview.template.html。生成JSON/HTMLの手編集をしない。統合仕様書は`python -X utf8 tools/build_spec_html.py`で生成。これらは実在するコマンドで、npmのゲーム検証コマンドは引き続き未実装。

## 守ること

- 公開情報を根拠に完全再現できたと宣言しない。推測・補完した数値を公式設定として記載しない。
- キャラクター・武器・スキルをデータ化し、キャラクター名による戦闘ロジックの条件分岐を書かない。
- 出典のない項目はevidenceStatus=original、sourceIds=[]を設定する。部分的に根拠がある項目はフィールドごとに区別する。
- 漫画画像は参照資料であり、ゲームのスプライトとして取り出して同梱しない。独自に作ったアセットと参照元を別管理する。
- 戦闘エンジンでDate.now、Math.random、DOMを使わない。整数時間、注入した乱数、安定した処理順で再現可能にする。
- サーバーの持つ全状態をそのままブラウザへ送らない。相手の設定、不可視敵の詳細、乱数種は対戦中非公開。
- 画面を一般的なカードゲームやリアルタイムアクションへ変更しない。原作画面の主要構成を先に再現する。
- 秘密情報や再接続トークンをログ／リポジトリに保存しない。

|---|---|
| npm run typecheck | 全パッケージの型検査 |

| npm run build | ブラウザとサーバーのビルド |

## 検証ループ

対象の受け入れ条件を確認 → 実装 → 対応する検証 → 失敗を修正。エンジン変更時はエンジン検証、通信変更時はサーバー検証、描画変更時は画面検証を行う。リリース前は全コマンドを通す。

見た目は自作の基準画面と比較し、漫画のコマとは手動で配置・形状を照合する。漫画の画素をそのまま自動テストの期待値にしない。未検証の項目を合格扱いしない。

仕様、補完数値、出典評価、画面構成を変更した場合は関連docsを同じ変更で更新。実際の起動手順ができた時点でREADMEを更新する。実装に必要な新しいblockerが見つかったら、その論点だけを具体的な選択肢とともに確認する。
