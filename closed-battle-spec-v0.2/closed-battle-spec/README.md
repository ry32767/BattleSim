# 閉鎖環境戦闘シミュレーション再現プロジェクト

PCブラウザで、行動を先に設定し、敵味方が同時に動く部隊戦を遊ぶ。原作キャラクターを自由に編成し、各部隊を1人でも最大4人でも操作できる。

2026年10月6日更新のv0.8仕様と地形確認ツール。ゲーム本体は未実装。R1.3エンジン仕様・実装工程を固定し、3段階の機能確認用マップM1.1を作成した。地形の不足はランク戦の建物・街路・遮蔽・高低差を主に参考にして補う。サイズ調整後58棟の仮配置は再現版の確定配置ではない。原作の完全な内部計算と独自補完を区別する。

射線・光学視界・死角は共通3D地形から判定する仕様G1を追加した。現在のマップ確認ビューアには未実装で、実装工程P2の必須条件としている。

トリオンを反映したメテオラの爆発・建物破壊、アイビスの貫通/破砕をD1へ追加。破壊後の射線・視界・移動と屋上の駒の処置も定義した。公式紹介と描写を基準にする校正パック・破壊処理は未実装。

シミュの原作規則を優先し、不明点をランク戦から補う。具体的なコマンド、時間境界、AP、競合、攻撃・防御、弾、地形破壊、秘匿、再生をR1.3へまとめた。D1.1の爆発・耐久値は実装用の固定基準で、原作との規模校正は未試験。

## 今回の成果と確認方法

- [実装可否・不足・詳細実装計画](docs/implementation-plan.md)：基盤と代表練習は実装可能、全64名の完成には実行データ作成が必要。各工程の作業内容と合格条件を収録。
- [R1.3ゲームエンジン仕様](docs/runtime-r1.md)：原作参照順、時間、コマンド、AP予約、命中・防御、武器、同時処理、弾、型、秘匿、再生と検証の契約。
- [M1.1マップ仕様](docs/map-spec.md)：原作の地形構成を参考にした独自市街地。全原作座標の復元ではない。
- [マップ確認ビューア](map-preview.html)をブラウザで開く。段階切替、俯瞰/平面、セル/屋上選択、始点指定→目的面の最小AP経路、グラスホッパー比較、JSON保存が使える。住宅20棟追加、道路幅の区別、階高調整、人物比較、屋上グリッド切替も反映。通信・追加インストール不要。

実ファイルは`data/maps/`に3JSON、`tools/`に生成・検証ツール、`docs/`に詳細契約。ビューアの経路は地形のみで、攻撃・霧・通信・駒の競合はまだない。

## 対象

- 行動設定、同時解決、結果とリプレイ。
- 将来、トリオン兵作成結果を同じ戦闘エンジンへ接続。

## 読む順番

ZIPを展開し、**仕様書.html**をPCブラウザで開くと、実際の参照画像3点と全照合表を一つの文書で読める。画像は埋め込み済み。本文内リンクは統合文書の各章へ移動する。

1. [仕様](docs/spec.md)：ゲームルール、補完規則、通信、受け入れ条件。
2. [画面再現](docs/visual-reference.md)：画像で確認した要素と再現基準。
   戦闘の原因表示、予定/実経路、リプレイ、PC操作の詳細も収録。
3. [全キャラ照合](docs/character-audit.md)：通常44名＋ヘルプ20名、装備・能力・既知スキルと未確認項目。
4. [全武器照合](docs/weapon-audit.md)：41装備種、武器表の匿名数値行、射程資料、55スキル名。
5. [出典](docs/sources.md)：資料の種類、確認内容、限界。
6. [作業規約](AGENTS.md)：実装・検証するAIエージェント向け。

[再現方針・ブロッカー](docs/reproduction-policy.md)は過去の監査記録。v0.7の処置は[実装計画](docs/implementation-plan.md)を参照。R0とR1を区別し、観測台帳の能力値は変更していない。地形作成とルール設計の完了は、全件コンテンツ・ゲーム実装の完成を意味しない。

v0.4では[ルール再監査](docs/rule-review.md)を追加し、セル単位の建物・屋上、旧補完の不足を記録した。表示確認モックは公式サイトを参考に外枠を改め、リプレイを独立ポップアップへ分離した。モックは戦闘エンジンの実装・全ルールの検証ではない。

v0.2では64名の通常装備を個別資料と一覧で照合した。原作全人物のゲーム化や64名のシミュ能力値の判明は意味しない。能力値は53/448項目が確認済み、395項目が未確認。段階IIIの勝利条件に出典差があり、5体差を暫定採用した。JSON/CSV台帳はdata/へ収録し、未確認値はnullまたは空欄。ゲームの動作確認を済ませたデータではない。

資料の整合性検証：`python -X utf8 tools/validate_spec.py`。地形の検証：`python -X utf8 tools/validate_maps.py`。ゲーム実装・対戦テストは未実施。

## 実装時の構成案

TypeScriptの共通戦闘エンジン、ブラウザ画面、権威サーバーを分離する。描画はCanvas系の2Dレンダラーを想定。ライブラリのバージョンと配備先は実装時に公式資料を確認して固定する。現時点で依存関係や起動コマンドは存在しない。

利用の流れは、ルーム作成／参加 → 部隊編成 → 操作担当割当 → 行動設定 → 同時行動 → 結果。タイトル、配色、独自アセットの最終デザインは変更可能。


v0.5では[レーダー・探知・タグ](docs/radar-tags.md)を追加。見やすいレーダー、盤面の疑問符、手動タグ、自動接触番号、視認による名前とアイコンへの切替をモックで確認できる。公式Twitter用アイコンの用途条件はS17に記録し、採用は保留。


v0.6はレーダーのキャラ表示をなくし、点と番号/タグへ統一。ユーザー指定の非公開・個人用ローカルモックでは公式ちびキャラのURLを盤面アイコンとして参照する。公式配布条件の記録とユーザーの採用指示は区別する。
