**v0.7追記：以下は過去の監査記録。** 今回の規則決定と残作業は[implementation-plan.md](implementation-plan.md)§2、式・時間・援護・イベントは[runtime-r1.md](runtime-r1.md)、地形は[map-spec.md](map-spec.md)を優先。B1/B5/B6の規則設計は固定したがコード未実装、B2〜B4の全件実行データは未完成。「今回は仕様のみ」「R1未定」は本監査作成時の記録で、今回の地形生成と規則決定を否定しない。

更新日：2026-10-06。今回は仕様作成のみ。ゲーム・補完マスターは未実装。閉鎖環境試験の戦闘シミュを維持し、実際の武器・個人・ランク戦の描写を不足情報の根拠として使う方針はユーザー確認済み。リアルタイムのランク戦モードは追加しない。

追加確認：計算は原作の挙動を再現するように推定し、武器はシミュ以外の原作情報も根拠にする。シミュ内で実際に起きた命中・防御・中断・撃破等も、性能や計算規則を絞り込む観測条件として使う。この方針は採用済みだが、具体的な式・係数は引き続き設計対象。

## 1. 再現の優先順位

シミュで確認できる数値・効果を優先し、不明な箇所は同じ時期・装備の原作描写、公式設定、二次整理から補完する。実戦を参考にしても、シミュのAP・警戒範囲・同時実行などの抽象化を維持する。地球の銃の弾速や殺傷力を、トリオン武器の確定値として使わない。

優先順は「直接確認したシミュ情報 → 対象時期の公式設定・描写 → 出典付き二次整理 → 原作に整合する独自補完」。資料同士が矛盾する場合は時期・装備・条件を確認し、都合のよい方だけを採らない。公式誌面を未確認なら、そのことを記録する。

R0のHP100・威力式・命中式は試作用として保存する。原作再現用R1は別RuleSetとし、本書の未決定項目が解決するまで完成版と呼ばない。試作値を自動でR1の既定値にしない。

## 2. 提示された能力値の使い方

[S15：キャラクターパラメーター](https://w.atwiki.jp/worldtrigger2ch/pages/383.html)を2026-10-06に確認した。ページはBBF由来の参考データとして14巻終了時点を示す。シミュの7項目と異なる8項目で、装備条件や欠損もある。BBF誌面自体を今回確認したわけではない。

以下は公式の変換表ではなく、補完設計の用途案。

| 参考項目 | 補完に使う箇所 | 直接置換できない理由 |
|---|---|---|
| トリオン | 出力・防御・継戦能力の傾向 | シミュ内の値や資源消費式との対応が未定 |
| 攻撃 | 武器別攻撃能力の傾向 | 武器威力・技術と重複加算しやすい |
| 防御・援護 | 防御と支援の傾向 | シミュでは別々の能力値。分割には追加根拠が必要 |
| 機動 | 移動・回避の傾向 | APや回避との倍率は分からない |
| 技術 | 精度・武器操作の傾向 | 武器基礎命中率との役割分担が必要 |
| 射程 | 装備と技量を含めた到達範囲の確認 | 評価値をセル数へそのまま置換できない |
| 指揮 | 連携スキル・指揮特性の検討 | 人間操作者の判断まで自動強化しない |
| 特殊戦術 | 固有戦法の候補調査 | 数字だけからスキル名・効果を生成できない |

合計値で強さを一本化しない。欠損はnullのまま保持し、0や平均値へ自動補完しない。通常・黒トリガー・角トリガー等の条件を区別し、採用対象外の装備時の値を混ぜない。14巻以降の成長・装備変更には別の根拠が必要。

既存data/のsimulation_statsは観測台帳として保持する。S15を使っても既知53/448項目が増えたとは数えない。補完マスター作成時は次を別々に持つ。

| 層 | 必須情報 |
|---|---|
| 参考能力 | characterId、時期、装備条件、項目ごとの値・出典・確認状態 |
| シミュ観測値 | 既存simulation_stats、出典。変更履歴を保持 |
| 補完値 | 対象フィールド、採用値、変換版、根拠、補完理由、代替候補または範囲 |
| 実行用プリセット | 観測値を優先して解決した必須値、装備、効果、contentVersion |

部分的に資料があっても、算出した値のevidenceStatusはoriginalとする。出典の存在と値の公式性は別。元資料のsourceIdsは参考能力側に残し、補完値から根拠レコードへ参照する。出典がない補完はsourceIds=[]。既存台帳を上書きしない。

## 3. ブロッカーと未確定事項

v0.4の追加再監査は[rule-review.md](rule-review.md)。地形のセル対応、演算粒度、角度制限、AP枯渇時のターン終了、視界共有、装備切替/解除、固有行動の論点を追加した。既存R0からの自動継承で解消済みにしない。

「ブロッカー」は対象機能の戦闘実装・完成宣言に先立って規則かデータを固定する必要があるもの。資料が完全に見つかることを必須にせず、根拠付き補完の採用でも解消できる。仕様・静止画面の検討は進められる。

| ID / 区分 | 現状と影響 | 解消案・完了条件 |
|---|---|---|
| B1 戦闘実装前 | R1の命中・防御・被害・撃破が未定。R0のHP制だけでは再現方針を判断できない | シミュ内の被害表示を優先調査。HP＋条件付き効果を基本案とし、部位損傷は個別効果で扱う案を比較。採用モデル・式・境界・同時処理を固定する |
| B2 キャラ有効化前 | 395能力項目が未確認。BBF評価からの変換も未定 | 既知4名のシミュ値との対応を検討し、変換・例外・適用不可条件を決める。全必須値の補完記録があるキャラのみ有効化 |
| B3 武器有効化前 | 41種の実行用数値未確定、匿名行の武器名結合も未確認 | 武器ごとにAP・待ち・威力・命中・射程・警戒範囲・遮蔽への作用を固定。特殊効果は別定義。未確認は補完と表示し、名前が不明の行を確定値として結合しない |
| B4 スキル有効化前 | 55名称があっても全所有者・条件・効果は未確定 | 発動条件、対象、消費、優先順、重複・連鎖上限、終了条件を個別に固定。未対応効果は利用不可理由を表示 |
| B5 連携実装前 | 援護値はR0では表示のみ。指揮・経験・個人特性との役割未定 | 援護が護衛・連携の何に作用するか、対象範囲・上限・AP負担を決定。手動指示と受動スキルを区別 |

| U1 暫定で進められる | 段階IIIの勝利閾値4/5の出典差 | 現仕様の5体差を暫定継続。公式確認後に新RuleSetへ反映 |
| U2 暫定で進められる | 元マップの寸法・配置・全地形が未確認 | 独自市街地を使用。原作場面の地形条件を検証シナリオに再現 |
| U3 数値調整前 | 1セルの実距離と1ステップの抽象化 | 主仕様の1秒/ステップを維持。距離・弾道の演出は戦闘判定を変えない。メートル換算は採用しない |

## 4. 補完の決め方と検証

1. 再現対象の時期・装備・場面と、シミュへの適用範囲を固定する。
2. 速度・射程・防御突破・連携など、条件付きの観測を出典とともに記録する。実戦の勝敗を単一能力の証明にしない。
   シミュ内の具体的結果も対象とし、行動前後のAP、距離、向き、装備、同時被弾、発動スキルなど判明した条件を保持する。一例から威力や命中率を一点確定せず、「この防御を突破できる」「この消費で予定が中断する」等の制約から候補を絞る。同じ結果を説明できる別の式が残る場合は代替案を記録する。
3. シミュ既知値を固定し、不足値にだけ候補の変換を適用する。防御・援護の分割など情報が不足する変換は独自補完として扱う。
4. 小シナリオで妥当性を確認する。比較条件は武器・距離・遮蔽・向き・探知・APを揃え、乱数を固定した例と複数種の分布を確認する。
5. 調整に使わなかった場面でも矛盾しないか確認する。原作の特定勝敗だけに合わせて係数を変えない。問題があれば式・スキル・条件を見直す。
6. 採用値・理由・検証結果・残る差を記録し、版を固定。新根拠は新しい版に反映し、旧リプレイを保持する。

検証候補は、同じ武器での技術差、同じトリオンでの装備差、正面防御と側背面、バッグワームの視界/レーダー差、単独攻撃と連携、攻撃消費による予定中断。これは今後出典付きケースを作るための観点であり、原作照合済みテストケースではない。

## 5. 受け入れ条件

- S15の参考能力とsimulation_statsを別保存し、参考値の追加で観測53項目の件数を増やさない。
- 同じ人物の異なる時期・装備条件を別レコードで管理できる。欠損・条件不一致を自動採用しない。
- 実行用の全必須値と全効果に、観測または補完の根拠をたどれる。未対応効果を無言で省略しない。
- R0とR1を区別し、R1で使用する全式・消費・同時処理・撃破規則を固定してから戦闘実装へ進む。
- 各補完案に比較条件と検証ケースを用意し、再現できない部分も記録する。
- B1〜B6の完了条件を項目別に照合し、代表縦切りの完了と全64名・全41装備の完成を区別する。

資料整合性はAGENTS.mdの検証手順、戦闘の妥当性は今後のエンジン試験・原作照合で確認する。今回は前者のみ対象。
