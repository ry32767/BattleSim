## 3. 調査で得た根拠と限界

2026-10-06に[S1公式25巻紹介](https://www.shueisha.co.jp/books/items/contents.html?jdcn=08X10000000023691400)、[S3通常演習整理](https://w.atwiki.jp/worldtrigger2ch/pages/430.html)、[S11地形分析](https://lshirasu.hatenadiary.com/entry/2023/02/25/203457)、[S16公式トリガー紹介](https://worldtrigger.info/article/trigger.php)を再確認。S3では150秒設定/15秒行動、6ターン、移動と上昇のAP、装備別扇形、追跡が説明されている。公式紹介ページから内部計算式は確認できない。

S11は断片的描写からの推定を明記した二次分析。32×32、34×34、35×36という寸法、点対称、特徴的地形を設計参考にするが、この記事の図を全セルの公式マスターとして転記しない。「三連民家」は同著者が付けた名称で、原作の確定名称と区別する。今回の中心市街地の配置・高さ・陣営開始位置は独自設計。原作描写との一致を数値で保証していない。

S3の近接連携は追撃APなし、射撃連携は追加消費あり、足止めは防御時の消費と待ち増加という整理を先行効果に反映する。特殊演習の援護と通常演習の援護は同一式と断定しない。その他の調査記録は[sources.md](sources.md)。

## 4. 実装構成と具体的方法

TypeScriptで共通エンジンを1個作り、練習とサーバーが同じ関数を呼ぶ。描画・ネットワークの時刻は判定へ渡さない。

| 所有範囲・予定パス | 方法・責務 |
|---|---|
| `packages/contracts/src/` | RuleSet/Map/Content/Plan/Event/Observationの型と入力schema。JSONのサイズ・範囲・未知IDを検証 |
| `packages/content/src/` | 台帳はread-only。別の参考能力・補完記録からcompileし必須値/効果の欠損で失敗。版固定のruntime-packを生成 |
| `packages/engine/src/geometry/` | 軸座標、面グラフ、Dijkstra、G1共通3D形状生成、候補supercover/AABB索引、BigInt有理数の線分-solid交差、角度内判定。描画メッシュも同じ形状生成結果を投影する |
| `packages/engine/src/resolve/` | pure `resolveTurn(state, plans, rule, content, seed)`。整数tick、安定順、イベント/次状態/ハッシュを返す |
| `packages/engine/src/observation/` | 視界/レーダー/識別/タグ。投影前は真状態、投影後は陣営公開型。失探で秘密位置を参照しない |
| `packages/replay/src/` | diff適用、checkpoint復元、当時開示の復元。再抽選なし。未知版/欠損を停止 |
| `apps/web/src/` | ReactのDOMで編成・一覧・フォーム、Canvas系2Dで盤面。カメラ・面選択・編集状態と試合状態を分ける |
| `apps/server/src/` | NodeのHTTP/WS、Room単位の直列command queue、締切、権限、再接続、24時間リプレイ保持 |
| `tests/fixtures/` | 地形・同時処理・秘匿・原作比較候補。出典付き観測ケースと独自受け入れケースを別種別で保存 |

技術選択：npm workspaces、TypeScript、Vite/React、PixiJS系2D描画、Node HTTP＋WebSocket、schema検証、Vitest、Playwrightを採用候補とする。**今回依存をインストールしていない。** セットアップ時に公式docsと互換性を確認して安定版の正確な番号をlockfileへ固定する。ライブラリ番号を架空に確定しない。初期はDBを導入せず、単一サーバーを採用する。

サーバーはroomごとにrevisionを単調増加させて直列受理。締切と同時刻のメッセージは受信時刻`< deadline`のみ受理。練習は固定敵プランで動かし、AI探索を先に作らない。描画は静的地形をキャッシュし駒・選択・霧・経路を別レイヤーにする。Web Workerは最初から必須にせず計測後導入。

## 6. コンテンツ完成に必要な作業の確定

1. 4名の観測7能力をそのまま別実行層へ参照し、時期と装備を明示。通常装備を全8枠埋めただけではsim用適合済みとしない。
2. 欠損395項目は、該当人物の同時期BBF/描写を調査→項目別候補→例外記録→採用。参考項目「防御・援護」を機械的に二つの公式値へ分割しない。記録のないキャラは無効。
3. 41種ごとにAP、待ち、出力、命中、射程、扇形、使用枠、対象、遮蔽作用、固有行動を埋める。変種を通常品と同じにする場合も明示的な補完記録が必要。
4. 55名称は条件/所有者/コスト/待ち/優先/上限/終期を埋める。所有者未確認を「誰も持たない」としない。未解決の人物は通常プリセットとして有効化しない。
5. 補完結果は`data/runtime/`に別保存し、`data/characters.json`等は上書きしない。原作比較候補と独自の境界試験を分ける。

完成マスターは今回作成していない。規則決定によってコンテンツ監査まで済んだと解釈しない。原作忠実度の残課題は「公式式」「III閾値」「全座標」「欠損能力・武器・所有効果」の根拠であり、これを待つだけの実装停止にはしない。
