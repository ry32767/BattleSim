## 1. 再現するものと、今回の独自決定

### ランク戦を参考にする具体的な範囲

参照の順序は「シミュ内で直接確認した地形 → 同種のランク戦の原作描写・公式資料 → 公式アニメ描写 → 二次整理 → 明示した補完」。シミュの画面だけで分からない建物の立面・屋根・道路幅・狙撃地点と遮蔽の関係を、ランク戦から補う。ユーザー指定の参照方針として採用し、シミュ地図と特定ランク戦ステージの全座標が同一という事実を確認したとは記録しない。

| 参考ステージ | 調査で確認した特徴 | 今回の採用範囲 |
|---|---|---|
| 市街地A | 低層住宅主体、所々の高い建物、道路と屋根上の戦闘。S18二次整理 | 住宅街の主な参考。屋根へ上る経路、屋根越しの射線、地表の隠れた移動を設計する |
| 市街地B | 密集した建物と路地、高低の建物、遮蔽の多い地形。S18二次整理 | ビル・路地・建物間の見通しの主な参考。配置の全転記ではない |
| 市街地C | 斜面の住宅地。S19公式紹介でも高低差と狙撃有利を説明 | 高所/低所の射線を比較するケースの参考。基本マップへ斜面を自動追加しない |
| 市街地D | 中央モールでの屋内戦。S20公式紹介 | 屋内・階層・通路の参考。内部を実装しない現段階でD再現マップと呼ばない |

S18は[ランク戦整理](https://w.atwiki.jp/worldtrigger2ch/pages/146.html)、S19は[公式第40話紹介](https://www.toei-anim.co.jp/tv/wt/wt01/episode/summary/40/)、S20は[公式3rd第3話紹介](https://www.toei-anim.co.jp/tv/wt/wt03/episode/summary/3/)。公式紹介は検索経由で本文を確認し、直接アクセスは403。今回それらの場面画像を目視済みとはしない。

### 再現配置を作る手順と出口

1. 住宅・店舗・ビル・工場の形状ごとに、ランク戦の原作巻/話/場面をreferenceレコードへ記録する。外観、高さの相対関係、街路との位置関係を分ける。アニメ固有の色や追加装飾を漫画の確定設定へ混ぜない。
2. シミュのL字・タワー・十字路等と形状を照合する。対応未確認なら「同種建物の参考」に留め、ランク戦A/Bの座標をシミュの座標へ自動コピーしない。
3. 描画輪郭とセルの対応を決める。高さ段への変換、道路のセル幅、未観測の裏側は独自補完としてフィールド別に記録する。実距離を根拠なく1セル何mへ換算しない。
4. 屋根からの射線、路地による遮蔽、道路横断時の露出、上る際の経路/APを同じデータで確認する。遮蔽と高所の優位が消える平坦化を避ける。
5. 根拠と対応表が揃った配置を新しいMap版として保存し、旧M1.0は残す。JSONの構造合格だけで原作照合済みとは判定しない。

M1.0で加えた高さ2/4のタワー足場と「全屋上へ通常移動で到達」は機能確認用の独自条件。再現版で全ての高所へ誰でも上れるよう、根拠のない足場を足す条件にはしない。代わりに通常到達面・グラスホッパー等で到達する面・利用不可面を区別して期待到達性を検証する。

ランク戦で描かれる建物破壊・壁抜き・屋内進入は参考資料に記録するが、v0.7.4のD1ではユーザー指定に基づく再現機能として追加する。原作シミュで全く同じ破壊規則が採用されていると確認した意味ではない。M1.0の不壊/内部なしは最初の実装範囲で、原作世界の普遍的な性質ではない。雪・天候・ステージ選択は今回の範囲へ追加しない。

以下の寸法・配置は既存の機能確認用M1.0。ランク戦からの再現照合済みマスターではない。

中央の広い十字路、住宅・ビル・工場・路地、選択できる屋上と高低差を再現対象とする（S3/S4と既存画像V1）。[S11地形分析](https://lshirasu.hatenadiary.com/entry/2023/02/25/203457)の寸法・点対称・地形分析は二次推定。建物の完全な輪郭、階数、座標表は公式確定情報として採用しない。

## 2. 座標・面・遮蔽の正典

論理位置はpointy-top axial `q,r`、cellId=`c:q:r`。表示用offset列`u=q+floor(r/2)`。n×nの範囲は`u,r ∈ [-n/2, n/2-1]`。隣接差分は`(1,0),(1,-1),(0,-1),(-1,0),(-1,1),(0,1)`。点対称変換は`(q,r)→(-q,-1-r)`、offsetでは`(u,r)→(-1-u,-1-r)`。この変換の中心はセル中心ではなくセル間にある。

| データ | 必須フィールドと制約 |
|---|---|
| Map | schemaVersion/id/version/stage/dimensions/renderScale/cells/buildings/spawnSlots/landmarks/evidenceStatus/sourceIds/rationaleSourceIds |
| Cell | id/q/r/terrain/roadClass/groundHeight/buildingId/roofHeight/surfaces/occluder。id/q/rは一意 |
| Surface | id/cellId/kind/z/walkable。地表セルはground1面、建物セルはroof1面。建物内部の地表面は存在しない |
| Building | id/name/cellIds/roofKind/category/evidenceStatus/sourceIds。占有セルはhex隣接で連結、全セルのbuildingIdと逆引き一致 |
| Occluder | 建物セルならsolidColumnの0〜roofHeight。地表ならnull。装飾用三角屋根は遮蔽を増やさない |
| SpawnSlot | team/index/surfaceId。地表、重複なし、両陣営は点対称。各段階必要数ちょうど |
| Landmark | id/label/cellId。盤面とレーダーは同じセルへ注目する |

建物の輪郭・壁・屋上は占有hexの集合から導出。屋上のcell境界と高さは切替表示し面の中心を選択できる。地形JSONへピクセル座標を保存しない。同棟で同高さの隣接セル境界には壁を描かず、外周の立面だけ描く。工場模様・勾配屋根・窓は自作装飾。

移動は隣接surface同士を結ぶ。上昇・消費はR1§2、高さ6を地表から直接選んでも経路が2/4の足場を使う。行先の高さだけで地表を通り抜ける経路を作らない。今回のビューアは地形だけの最小AP経路で、駒同士の競合・戦闘APは予測しない。

射線・光学視界の正典は本章の「3D判定契約 G1」。従来の面高さ+1と始点/終点建物除外による近似はR1.1で置き換える。判定器の実装はP2。

## 3D判定契約 G1（v0.7.3 / 実装予定）

ユーザー指定により、射線・光学視界・地形遮蔽はマップから生成した共通の3D形状で判定する。俯瞰画面の重なり、平面セルの遮蔽フラグ、始点と終点の高さ比較だけで成立を決めない。この節とR1.1が旧R1.0の遮蔽・固定死角の規則より優先する。原作の公式判定方式ではなく、このアプリの実装契約。

### 座標と形状の正典

- 判定空間は右方向X、盤面下方向Y、上方向Z。セル中心はX=1732051×(2q+r)、Y=3000000×r。hex頂点の中心からの差分は(0,±2000000)、(±1732051,±1000000)。全座標を固定整数で保持する。
- 高さ1段=1400000をG1の固定スケールとする。これはM1.1のhex半径10・階高7と同じ比率を採用した独自補完で、メートル換算ではない。論理的な面高さzに対してZ=z×1400000。AP・上昇制限の段数はそのまま維持する。
- 初期の建物は占有hexごとの底面から屋上までの閉じた六角柱の和集合。屋上は支持面、外壁と屋上面は遮蔽物。地表も支持面として扱う。同棟の内側にある重複面を外壁として描かない。
- 形状生成器を唯一の正典とし、判定用solid・支持面と表示用メッシュを同じ入力から生成する。初期gable/sawtoothは平坦な屋上の装飾と明示する。屋根傾斜、塀、手すり、張り出し、窓、屋内通路が遮蔽へ影響する版では、表示だけを足さず対応する3D solid/開口/支持面も追加する。
- G1の身体高さは高さ1段の0.6倍（840000）、目は足元+0.54段（756000）、発射点は+0.40段（560000）。いずれもセル中心のXY。装備別発射点や姿勢変更は将来の版で明示する。画像の頭や銃口のピクセル位置を判定へ逆算しない。
- カメラ投影・拡縮・回転・平面切替・透過表示で判定は変わらない。通常描画はG1と同じ形状比率を投影する。強調用アイコンは当たり判定の形状と区別する。renderScaleはカメラ/表示設定であり、判定空間を変更する権限を持たない。

### 射線・視界・死角

| 判定 | G1の規則 |
|---|---|
| 直射の射線 | 発射点→対象の足元+0.35段（490000）の線分が地形solidへ交差しなければ通る。命中/回避/防御はその後の別判定 |
| 敵の光学視認 | 観測者の目→対象の足元+0.15/0.35/0.55段（210000/490000/770000）の3点へ線分を引き、少なくとも1本が通れば遮蔽条件を満たす。身体の連続体の一部可視を完全計算したとは扱わない |
| 面の可視表示 | 目→対象支持面中心+0.01段（14000）の線分で判定する。面の可視マスクと敵の視認結果は別々に保存し、面が暗いことだけで見えている敵を消さない |
| 屋上から足元 | 自分が立つ建物も判定対象。屋上の縁や外壁が下向きの線分を遮れば死角になる。高さ差2・隣接1セルという固定除外は廃止 |
| 視認と射撃の違い | 頭部側の点だけ見えて発射点から胴の点が遮られる場合は「視認可・射撃不可」。味方共有の視認があっても、射手自身の射線を再判定する |
| 観測条件 | 視界半径6+min(3,z)、陣営共有、レーダー秘匿、装備効果はR1.1の別条件。レーダー検出に光学遮蔽を自動適用しない |
| 射程・方向 | 初期は水平hex距離と水平扇の既存契約を維持し、3D遮蔽と分離する。斜距離射程・上下照準角の制限は未採用。曲射/誘導/爆発/貫通は効果別の経路・3D作用条件が定義されるまで直射扱いに自動変換しない |

移動中はR1の出発面を論理位置として判定する。演出補間中の見かけの位置で射線・視界を再判定しない。初期は他のユニットを地形遮蔽物として扱わず、味方の体で射線を遮る規則を追加しない。

始点・終点セルの建物を丸ごと除外しない。線分内部0<t<1でsolidの内部または境界に接したら遮断する。端点だけの接触を除き、屋根面/辺/頂点への接線も遮断。共有境界を横切る候補hexはsupercoverで漏れなく列挙するが、最終判定は各3D solidとの線分交差で行う。閉じた凸多面体に対する区間クリッピングを整数/有理数（BigIntの分子・分母比較）で実装し、端点での高さ一回比較や浮動小数epsilonへ依存しない。始点と終点を交換した同一線分の地形遮断結果は一致させる。観測者の目の高さや視界半径が異なる視認結果の対称性は要求しない。

候補のAABB/空間索引→正確な交差判定の順で実装する。結果はclear/blocked、最初の遮蔽solidId・cellId・交点・線分パラメータを返し、同位置の複数遮蔽はsolidId順に固定する。完全記録へgeometryVersion・形状入力ハッシュ・始終点・対象サンプル・遮蔽点を保存。対戦クライアントには陣営観測で開示可能な結果だけを送る。

### 実装・版管理と受け入れ条件

現行M1.1 JSONと確認ビューアは3D判定器を実装していない。G1を追加する際はgeometryVersion/geometryScaleを持つ新Map版M1.2以降へ保存し、G1のみならruleVersion=R1.1、D1も含む版ではR1.2とともに試合開始で固定する。既存M1.0/M1.1へ判定メタデータを後付けして旧リプレイの結果を変更しない。

| ID | P2で実装して検証する合格条件 |
|---|---|
| G1-T1 | 地表同士の間に壁があれば遮断、同じXY経路でも屋上より高い線分は通過 |
| G1-T2 | 屋上の縁に遮られる低所と、十分離れて見える低所を同じ交差判定で区別。自セルsolidの一括除外なし |
| G1-T3 | 頭側だけ見えるケースで視認可/射撃不可。味方共有視界で射手の遮蔽が消えない |
| G1-T4 | 屋根面・共有辺・頂点に接する線は遮断、そこから離れた線は通過。同一線分の逆向き判定も一致 |
| G1-T5 | 俯瞰/平面/カメラ変更/透過/画面サイズ変更で結果不変。描画外壁・支持面と判定形状が同じ生成結果 |
| G1-T6 | 同じ版・tick・入力ならサーバー/練習/リプレイで同じ結果。移動演出中の補間位置を使わない |
| G1-T7 | 面の可視・敵視認・レーダーを区別し、遮蔽ID/交点/未視認敵の高さから秘密情報が漏れない |

これらは受け入れ条件の追加であり、今回は実装・合格していない。

## 爆発・建物破壊契約 D1（v0.7.4 / 実装予定）

ユーザー指定により、トリオンに応じた爆発範囲・威力と建物破壊を必須機能へ追加する。従来の「不壊」はM1.0/M1.1の静的試作条件として残し、完成版の制限にはしない。G1を動的3D地形へ拡張し、破壊後の形状から射線・視界・支持面・移動経路を再計算する。

### 根拠と照合基準

[S21公式トリガー紹介](https://worldtrigger.info/article/trigger.php)の紹介画像を目視。メテオラは広範囲を攻撃する炸裂弾で、トリオン量の調節により爆発規模を設定できる。アイビスは一撃の威力を重視する狙撃銃。公式紹介から数値半径・建物耐久・トリオンとの数式は確認できていない。

[S22公式3rd第12話紹介](https://www.toei-anim.co.jp/tv/wt/wt03/episode/summary/12/)は千佳のメテオラで味方ヒュースも巻き込む爆撃作戦を説明。[S23公式2nd第6話紹介](https://www.toei-anim.co.jp/tv/wt/wt02/episode/summary/6/)は千佳のアイビス砲撃を説明する。これらの本文は検索経由で確認し、建物の寸法測定に使った資料とはしない。

ユーザー提示の「千佳のアイビスで建物1棟規模、メテオラで巨大モール半壊」を必須の規模照合ケースU-D1/U-D2として採用する。モール半壊はS24二次整理でも確認したが、今回は原作該当コマを直接照合していない。ユーザーの再現要求と公式資料の確認結果を別レコードにする。「どんな建物もアイビス一発で全消滅」「全てのメテオラ弾がモール半壊」と一般化しない。分割なし大玉・単発と、分割弾・連射の条件を分ける。

### トリオンと武器特性

- 入力は実行パックのtrionと、版固定の武器別trionResponse曲線。シミュの千佳25という観測値とBBF参考38を同じ尺度で合算・置換しない。原作能力を用いる補完パックは尺度変換・時期・参照を別保存する。
- 武器ごとに対ユニット威力、構造物破壊出力、爆発規模、貫通、弾速、射程への影響を分離する。アイビスは威力/貫通・局所破砕を中心に扱い、メテオラと同じ球形爆発を一律に付けない。イーグレット等へも同じトリオン増幅式を自動適用しない。
- メテオラの弾ごとの予算は `E=floor(blastBudget×trionResponse(trion)×chargeRatio×blastAllocation/divisionCount)` を固定小数点で計算する。chargeRatioとblastAllocationは0〜1、分割数は正整数。同じ生成予算の分割で総予算が増えない。銃型・擲弾銃型・射手型は別profileで保持する。
- 初期補完モデルは `P0=floor(powerCoefficient×E)`、`R=integerCubeRoot(floor(volumeCoefficient×E))`。RはG1の3D座標単位、P0はそのprofileの中心威力。球体範囲の体積へ予算を割り当てるための独自近似で、公式の物理式ではない。対ユニットと対構造物の係数は別とし、HP100を建物耐久へ流用しない。
- 距離減衰は `P(d)=floor(P0×max(0,R-d)/R)`（R>0）。距離dは3D整数距離。範囲候補はd²<=R²で列挙し、境界d=Rは威力0。整数平方根/立方根・固定小数点の丸め順を版固定する。
- blastBudget、応答曲線、係数、材料耐久、貫通減衰、弾速、起爆遅延、AP/待ちの具体値は調整パックへ格納する。公式値が未確認の欄を0/適当な数値で埋めず、規模照合が通る値を独自補完として採用する。係数未定のprofileは通常演習で選択不可。今回、半径や係数が校正済みとは報告しない。
- トリオン関連スキルによる範囲補正は能力曲線と別のeffectとして記録し、同じ増幅を二重適用しない。未確認の「トリオン・極大」を勝手に固定加算へ変換しない。

### 起爆・3D作用・構造物

1. FIRE_ATは現在可視の地形点または既知の3D点への地形射撃を許可する。レーダーだけから敵の未知の高さへ自動照準しない。直接攻撃の現在視認条件とは別コマンドで、不可視敵が爆風に巻き込まれる場合は実在位置をサーバー内で評価する。
2. projectileにposition/velocity/remainingBudget/fuse/owner/profileを持たせ、固定tick間の移動線分とG1形状を交差判定する。メテオラは最初の衝突点で版固定の遅延後に起爆。直射・投射・曲射・置き弾はprofile別に定義し、未対応方式を直射へ黙って置き換えない。生成中/設置済み弾への被弾起爆も弾状態と耐久/起爆条件を定義して対応する。
3. 爆発は3D球体候補から、爆心→対象身体サンプル/構造要素への遮蔽と材料厚を評価する。発射位置→敵の直射線がなくても、着弾点から爆風が届けば被害を与える。陣営フィルタで味方/発射者を除外しない。爆発命中に通常射撃の命中抽選を再度掛けず、回避/防御の適用条件はprofileへ明示する。
4. 衝突面上の爆心は最初の衝突時刻の有理数座標で保持する。端点の接触だけはG1と同じ規則で除き、壁の反対側へ始点を任意のepsilonでずらさない。着弾した壁も構造被害の対象。初期補完では爆風線上の要素を近い順に調べ、耐久に応じた予算を消費して破壊/貫通し、予算が尽きれば後方へ届かない。単に壁があるから爆風も建物被害も全て0にしない。
5. 各構造要素にelementId/3D solid/materialId/maxDurability/currentDurability/supportIdsを持たせる。初期の分割単位は占有hex×高さ1段の六角柱。破壊した部分だけsolidを除去し、建物ID全体を一括削除しない。これは粗い体積モデルで、窓や室内まで再現した建物ではない。
地盤は初期D1では不壊とし、クレーター・地下掘削を追加しない。アイビスは3D直線上の構造要素を近い順に調べ、厚さ/材料に応じて貫通予算を消費し、局所要素の破砕と支持喪失を計算する。見た目の衝撃エフェクトをメテオラの球体爆風へ置き換えない。貫通予算が尽きればその位置で停止する。

6. 同群の各爆発は群開始形状から寄与を計算し、要素への構造被害を合算して一括確定する。同群の先に処理した爆発だけが穴を利用する結果を避ける。各爆発の貫通予算は独立に消費し、同要素の耐久消費を爆風サンプルの本数分で二重計上しない。破壊・支持関係を確定してから、次の優先群/次tickが新形状を使う。
7. 支持グラフで地盤へつながらなくなった要素を崩落として除去する。初期は同じhex列の下段が上段を支える保守的なモデル。横梁支持を再現する版ではsupportIdsを追加する。飛散瓦礫・煙・火災を新たな遮蔽として扱う効果は初期未採用、演出だけで視認を変えない。
8. 支持面喪失時は駒を同じXYの最も近い下方の生存支持面へ強制下降する。任意ジャンプと区別しAP不要、初期は落下ダメージなし。着地競合は安定unitId順で予約し、競合駒は候補面グラフ距離→下降距離→surfaceId順の最寄り空き支持面へ配置する。盤面全体に合法な空き支持面がなければ地形喪失によるベイルアウトとして理由を記録する。未着地移動は支持面/行先の存在を再検証し、成立不能なら予約取消・未実行移動AP返却、経過時間は維持する。
9. geometryRevisionを上げ、変更AABBに関係する遮蔽/視界キャッシュと面グラフ/経路を無効化する。破壊された屋上IDを有効な行先として残さず、予定は未実行部分を再計画し、不可なら理由付き停止。描画・陣営観測・レーダー地形表示も同じrevisionから生成する。

完全イベントに起爆点/予算/対象/構造被害/除去要素/崩落/強制下降/取消/geometryRevisionを保存し、checkpointへ残存地形を含める。対戦中は可視/聴取等の開示規則に従った地形変更だけを通知し、不可視領域の破壊通知から敵位置や射手名を漏らさない。試合後の全体再生は完全記録、当時視点は当時の観測diffを使う。旧不壊マップへ遡及適用しない。

### 決定性のある3D作用

1. 発射点はG1、照準は合法な既知3D点。projectileはorigin、aim、travelledDistance、speed、ageTicksを整数保存し、位置をorigin＋(aim-origin)×travelledDistance/lengthの有理数で求める。lengthは整数平方根の切上げ。aim到達でも起爆する。丸め累積で軌道がずれない。
2. 各tickの飛翔線分とsolid／ユニット身体の交差を調べる。ユニット身体はG1中心の半径280000・高さ840000の閉円柱。距離比較は二乗整数／有理数、交点時刻は根の有理区間として厳密比較し、未分離なら区間精度を上げる。最初の交差を採用、同時刻は地形→ユニット→ID。所有者との衝突は無効、味方との衝突は有効。他の駒はG1の視界遮蔽物にはしない。
3. 座標距離の算出は有理数の距離二乗から整数平方根の切上げ。球体内外は丸め前のd²<=R²で確定し、減衰用dだけ切上げる。構造への距離はsolid最近接点、対人はG1胴サンプル490000。爆心を任意epsilonでずらさない。半径0は不正profile、球の境界は被害0。
4. 爆心→対象サンプルの線上の構造要素を交差時刻順に並べる。経路吸収=floor(currentDurability×min(交差長,1400000)/1400000)。境界だけの接触は満厚吸収、爆心が壁面にある場合も着弾壁を含める。出力が吸収以下ならその先の被害0、超過分だけ次要素へ届く。耐久0要素は通過する。
5. 各構造要素への基本寄与は距離減衰後の構造出力から、その要素より手前の吸収を引いた値。同一爆発から同一要素へは最大寄与1件だけを記録し、対人の遮蔽線から追加構造損傷を発生させない。同群の別爆発の寄与は合算する。各線は独立の局所圧モデルで、全方向へ分配したエネルギー総量保存を主張しない。
6. アイビスは射線上の要素の吸収を貫通予算から減らし、最初に予算が尽きた位置で停止。貫通に成功した要素と、停止要素へ残予算の構造被害を与える。局所破砕円柱は発射点から停止点まで、円柱交差要素へ距離軸からの線形減衰を掛けた構造出力を1回適用。体積円柱は壁抜き判定の貫通予算を増やさず、ユニットを範囲攻撃しない。対人到達時はfloor(20×T×remainingPenetration/initialPenetration)。その最初のユニットで弾を終了する。
7. 構造要素はcell×高さ1段、elementId=buildingId/cellId/layerIndex。下層だけで支持する。耐久0を除去し上の非支持層を全除去、各柱の最上層にroof、全層消失時はgroundを生成する。D1の支持喪失・強制下降・空き面探索を群末に実施し、地形喪失競合で使用する距離は更新後の面グラフから計算する。内部侵入用の部屋・扉・梁は生成しない。

### 校正fixtureと受け入れ条件

fixtureはエンジン実装時にtests/fixturesへ作成する。住宅は2×2 offsetセル・高さ2・residential・下層支持、モールは6×6 offsetセル・高さ3・reinforced・下層支持に固定し、G1固体体積で除去比を計算する。住宅占有はoffset(u,r)=(0..1,0..1)、originは(-1,0)のG1発射点、aimは(0,0)のZ=700000。モール占有はoffset(u,r)=(-3..2,-3..2)、originは(-4,-1)のG1発射点、aimは(-1,-1)のZ=700000。q=u-floor(r/2)で変換する。両fixtureはoffset -8..7の16×16地表盤面、周辺建物なし。同じ座標をT6/T25で使用し、全座標／origin／aimをfixtureに保存する。実原作建物の寸法復元ではなく独自の校正形状。

U-D1はT25アイビス1発で住宅の初期体積75%以上除去、U-D2はT25／N1のメテオラでモール40〜60%除去かつ一部残存。通常比較T6は同条件で高トリオンより除去量が少ない。75%も本プロジェクトの「1棟規模」の測定定義。人物名による特例、fixtureだけの耐久変更は禁止。基準B1が目標に合わなければ数値を別版で修正し、合格するまで通常完成パックへ出さない。

今回固定したのは計算方法と基準係数で、上記fixture生成・エンジン計算・体積比較は未実施。既存M1.1 JSONに破壊耐久を後付けせず、新Map版へ分割構造と材料を生成する。
