# C1/C2実行コンテンツとM1.2

`npm run content:build` は `tools/build-content.ts` の明示データから `data/runtime/` と `data/maps/M1.2/` を再生成する。元の `closed-battle-spec-v0.2/closed-battle-spec/data/`、観測値、M1.0、M1.1は入力専用。`source-lock.json` にそのSHA256を固定し、変更された入力からの再生成を拒否する。

既定の `content` は `C2.0-calibrated`、`baseContent` は元の `C1.0-sandbox`。`content-pack-b1.json` と `manifest-b1.json` はB1の係数・未校正flagを保持する。C2は同じ人物・装備・効果とR1.3アルゴリズムを使い、独立fixtureの目標に合わせた武器係数だけを別版にした。

## 人物能力とプリセット

64名ごとの七能力448項目を個別に選択した。既存の53観測項目（うち四名は七能力すべて）を保持し、残395項目はC1独自補完。各項目に値、候補幅、時点、C1変換版、参照ID、採用理由、検証ケースIDを保存する。コンパイラは欠損を平均や0で埋めない。観測と補完の数は `overrides` の `evidenceStatus` で区別できる。

BBF参考五能力は [キャラクターパラメーターの二次整理](https://w.atwiki.jp/worldtrigger2ch/pages/383.html) を2026-10-06に確認し、47名分の `bbf-references.json` に分離した。この資料は14巻時点。現在の選抜試験シミュ値への直接転記ではない。防御・援護を二つの公式数値へ分割したとは扱わず、人物ごとの別候補として採用した。雨取の観測トリオン25をBBF38へ置換しない。ヒュースの角付き近界装備の値を現在の通常装備へ転用しない。

`char_NN` は所有スキルの全件確認が済んでいない通常候補で、全64件とも無効。`char_NN-supplemented` は選択時点の通常装備と個別能力、明示した独自スキル所有割当を使う別スナップショット。原作の通常本人と同一の完成監査済みマスターではない。 `preset-restrictions.json` に確認済み所有効果、独自追加効果、未実装による省略装備・省略効果を人物ごとに保存する。省略がなくなっても通常所有効果の完全性は未確認のまま。

`char_26-training`、`char_27-training`、`char_28-training`、`char_35-training` は隠岐・三雲・香取・樫尾の既知七能力を使う練習用別ID。四人の通常候補と混同しない。健脚を採用する補完プリセットではAP行に含めたことをflagで明示し、エンジンの二重加算を防ぐ。練習版は確認済みの先行効果だけを使う。

段階I/II/IIIのヘルプ候補は出典台帳の全4/7/9名。部隊一覧は44名を十一組として補完IDへ解決する。ヘルプの複数選択を重複させず、練習の基本四枠ともIDを分ける。

## 装備と効果

41装備を一つずつ定義し、銃形と改造品を独立IDに保持する。攻撃装備にAP、待ち、出力、命中、距離、扇、対構造出力、占有枠を必須化する。支援・専用optionの攻撃出力・命中・射程はnullで、専用作用の距離はoptionsへ記録する。EG対人140/構造60、LT対人80/構造20、IBの20×trion、射手メテオラB1はR1.3/D1.1に従う。旧R1.0のEG18×trionは使わない。匿名V3武器候補行は確定IDへ自動結合していない。

[S3の通常演習整理](https://w.atwiki.jp/worldtrigger2ch/pages/430.html) を2026-10-06に確認し、55名称すべてについて個別kind、条件、対象、フック、優先、AP、待ち、倍率・値域、stackKey、上限、終期、可視性を別定義にした。記述にない数値倍率・期間の取り扱いはC1独自補完。八つのR1先行効果は独自の共通バフへ置換しない。その他の所有割当もC1独自設計として通常所有者の根拠と区別する。現在の可否は `manifest.json` と各 `enabled/status` が正典で、名前や定義の存在だけでは実行済みと扱わない。

コンパイラは未知ID、七能力欠損、重複presetID、必須の出典記録欠損、無効効果を持つ有効プリセット、支援への不適切な攻撃値、違うルール版を拒否する。active MAIN/SUBの二枠占有と専用optionの装備依存は `validateWeaponAction` で検証する。

元・攻撃手の作用を明確にするC1補完として、SN/GU/SHがブレードを使う場合の追加AP1をprofileへ明示し、その効果で免除する。AT/ARは追加対象外。タイマーはメテオラのfuse10tickと、改造ハウンドの発動10tick遅延を別作用にした。占有セルへのエスクードは駒を新しい屋上へ持ち上げ、エスクード攻撃を持つ使用者からAP3減少・待ち1を与える。これらの未記載細部はC1の運用補完で、観測台帳の確定値ではない。

レイガストはMAIN/SUBごとにattack/shieldモードを選ぶ。shieldではその側の自動攻撃を停止し、合法な防御扇内の被弾に受けAP1/待ち1を適用する。既定はattack。`options.supportsShieldMode=true` のprofileだけがモード入力を受け入れる。

技能の固有行動メニューは `values.activation='manual'` の六件（改造鉛弾・鉛弾狙撃・鉛弾追尾・合成弾・全武装適正・変化弾適正）だけを選ぶ。エスクード攻撃とテレポーター適正は装備の固有行動に伴う自動作用で、フックがCOMMAND_STARTでも技能として手動起動しない。残り49件は `passive` を明示する。

## 地形

M1.1の配置を維持し、新しいM1.2 JSONへcell×高さ一段の構造要素を生成した。材料は住宅300、工場600、ビル1200のB1基準。各柱の下段だけを支持IDにする。ground、roof、建物占有は同じ入力で生成する。G1のsolidと表示はエンジンの共通形状生成器がこのM1.2を使う。

M1.2はM1.1の仮配置に動的構造契約を加えた版で、原作の全座標復元版ではない。ランク戦との配置照合M10/M11と実距離換算は未確認。B1の未達結果は `calibrated=false` の別パックで保存し、以下のC2校正と分ける。

## C2プロジェクト目標の校正

住宅2×2×2段（8要素）とモール6×6×3段（108要素）を別fixtureで測定した。初期地形・材料・耐久を変更せず、住宅300、工場600、ビル1200の契約を保持する。fixture全体のSHA256を記録して再測定時に照合する。seed19、全量charge/爆発割当、分割N=1、T6/T25を使う。

| fixture | B1 T6 | B1 T25 | C2 T6 | C2 T25 | C2目標 |
|---|---:|---:|---:|---:|---|
| 住宅・アイビス | 4/8（50%） | 8/8（100%） | 4/8（50%） | 8/8（100%） | T25で75%以上、T6より大 |
| モール・メテオラ | 0/108（0%） | 18/108（16.67%） | 0/108（0%） | 51/108（47.22%） | T25で40〜60%、57要素が残存、T6より大 |

アイビスは厳密な有限円柱を使う。地形FIRE_ATのクリック点は方向を定め、実射線は水平profile射程・最初の身体・貫通予算切れのいずれかまで続く。円柱は発射点からその実停止点までに切り詰める。射線をクリック点で打ち切った旧測定や端面外を含めた近似の6/8を校正値として使わない。最終判定のB1住宅は8/8で目標を満たし、局所破壊係数500000と貫通予算係数12を維持した。

メテオラは共通予算係数を12から26へ校正した。射手・擲弾銃・突撃銃の元の個別係数12/14/10に同じ26/12倍を適用し、整数丸めで26/30/22となる。人物名・fixture名による分岐はない。射速・弾道・fuse・材料は維持する。

`calibration-report.json` はB1/C2の実測結果、`calibration-overrides.json` は各係数の旧値・新値・理由・検証IDを保存する。試験はC2全パックの実際のprofileをfixture用IDへ付け替えるだけで使用し、数値を試験用に差し替えない。`calibrated=true` はこのプロジェクトのU-D1/U-D2達成を表し、漫画の実寸照合、通常所有スキルの完成、公式内部式の確認は表さない。
